The AppShell structure:

```typescript
import { ReactNode } from 'react'
import { Header } from '@/components/layout/Header'
import { Sidebar } from '@/components/layout/Sidebar'
import { RightPanel } from '@/components/layout/RightPanel'
import { MobileDock } from '@/components/layout/MobileDock'
import { CommandPalette } from '@/components/command/CommandPalette'

export function AppShell({ children }: { children: ReactNode }) {
  return (
    <>
      <div className="app-shell">
        {/* Header: spans full width, row 1 */}
        <header className="app-shell-header">
          <Header />
        </header>

        {/* Sidebar: left column, row 2 */}
        <aside className="app-shell-sidebar">
          <Sidebar />
        </aside>

        {/* Main content: center column, row 2 */}
        <main className="app-shell-main">
          <div className="app-shell-content">
            {children}
          </div>
        </main>

        {/* Right Panel: right column, row 2 */}
        <aside className="app-shell-panel" data-visible="false">
          <RightPanel />
        </aside>

        {/* Mobile Dock: fixed position, only visible on mobile via CSS media query */}
        <MobileDock />
      </div>

      {/* Command Palette: portal-based overlay, renders at root level */}
      <CommandPalette />
    </>
  )
}
```

The CSS classes `.app-shell`, `.app-shell-header`, `.app-shell-sidebar`, `.app-shell-main`, `.app-shell-panel` are defined in globals.css (Plan 02). They establish the CSS Grid layout with grid-template-columns referencing CSS variables.

The `data-visible="false"` on app-shell-panel starts the panel hidden by default. The RightPanel (a client component) will override this based on layout state.

The `app-shell-content` div inside `app-shell-main` is the slot where page contents render. Individual pages can apply their own max-width constraints (e.g., `max-w-content-timeline` for the timeline page).

IMPORTANT for executor: The imported components (Header, Sidebar, RightPanel, MobileDock, CommandPalette) are created by Plans 05-08. If any of these files don't exist yet when you create AppShell.tsx, create STUB placeholders for them (minimal: `export function ComponentName() { return null }`) so the build doesn't fail. The actual implementations will be filled in by the respective plans.

Do NOT add any 'use client' directive to AppShell.tsx — it is a Server Component. The imported sub-components (Header, Sidebar, etc.) will each have their own 'use client' directives.
