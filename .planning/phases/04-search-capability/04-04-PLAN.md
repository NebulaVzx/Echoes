  <action>
Create scripts/e2e-search-test.sh that automates end-to-end search verification.

The script should:
1. Check all services are healthy (Gateway, Memory, Vectorizer, PostgreSQL, Redis)
2. Register a test user and obtain JWT token
3. Create 3+ text memories with varied content (e.g., "Go concurrency patterns", "Python asyncio tutorial", "Rust memory safety")
4. Wait for processing to complete (poll until processing_status = "completed")
5. Call Vectorizer /encode directly to verify it works: `curl -s -X POST http://localhost:8003/encode -H "Content-Type: application/json" -d '{"text":"Go concurrency"}'`
6. Call search API via Gateway: `curl -s -H "Authorization: Bearer $TOKEN" "http://localhost:8088/api/v1/search?q=Go%20concurrency&limit=5"`
7. Verify search response: success=true, results array non-empty, each result has similarity >= 0.75
8. Get one memory ID and call related API: `curl -s -H "Authorization: Bearer $TOKEN" "http://localhost:8088/api/v1/memories/$ID/related?limit=3"`
9. Verify related response: success=true, results length <= 3, no self-reference
10. Test Redis cache: call same search twice, second should be faster (or verify Redis key exists)
11. Test error case: search with vectorizer down should return 503
12. Clean up: delete test memories and user

Script requirements:
- Use `set -e` for strict error handling
- Use `echo` with clear section headers
- Use `jq` for JSON parsing (check if installed)
- Set `TOKEN`, `USER_ID`, `MEMORY_IDS` as variables
- Print PASS/FAIL for each test section
- Exit with code 0 on success, 1 on failure

Example structure:
```bash
#!/bin/bash
set -e

BASE_URL="http://localhost:8088"
VECTORIZER_URL="http://localhost:8003"

echo "=== Echoes Search E2E Test ==="

# Section 1: Health checks
echo "[1/8] Checking service health..."
# ...

# Section 2: Create test data
echo "[2/8] Creating test memories..."
# ...

# etc.
```
