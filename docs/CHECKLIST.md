# Echoes (拾忆) 闭环质量检查清单

> **原则：代码写完只是50%，测试通过+文档对齐+视觉闭环才是100%。**

## 使用方式

每个 Sprint 结束时、每次提交前，逐项检查并打勾。

---

## 一、代码质量检查

### 1.1 编译/构建
- [ ] 所有 Go 服务 `go build` 无报错
- [ ] 所有 Python 服务可正常启动
- [ ] Next.js `npm run build` 无报错（或 `npm run dev` 正常）
- [ ] Docker Compose `up -d` 所有服务 healthy/running

### 1.2 功能测试
- [ ] 新增 API 接口通过 curl/Postman 测试
- [ ] 错误场景测试（无效参数、未认证、重复数据）
- [ ] 边界条件测试（空输入、超长内容、特殊字符）
- [ ] 前端交互测试（表单验证、按钮状态、跳转逻辑）

### 1.3 安全
- [ ] 无硬编码密钥/API Key
- [ ] 无 SQL 注入风险（使用参数化查询）
- [ ] 敏感字段不在 JSON 响应中暴露（password_hash 等）
- [ ] OAuth state 参数有效（生产环境严格校验）

---

## 二、文档对齐检查

### 2.1 PRD.md（唯一数据源）
- [ ] Sprint 完成状态与 PRD 第10章一致
- [ ] 已实现功能在 PRD 中标记 `[x]`
- [ ] 未实现功能标记 `[ ]`
- [ ] 里程碑验证项全部测试通过

### 2.2 PROGRESS.md
- [ ] Sprint 状态与 PRD 一致
- [ ] 新增/修改的完成项已标记 `[x]`
- [ ] 待解决问题列表已更新
- [ ] Day X 记录包含：做了什么、测试结果、遇到的问题

### 2.3 CHANGELOG.md
- [ ] 当前版本号正确（语义化版本）
- [ ] 新增功能按模块分类
- [ ] Bug 修复有描述
- [ ] 技术栈更新已记录
- [ ] 版本链接正确

### 2.4 API.md
- [ ] 新增接口已文档化（请求/响应/错误码）
- [ ] 修改的接口响应格式已更新
- [ ] 错误码表完整（含新增的错误码）
- [ ] 健康检查版本号与实际代码一致

### 2.5 ARCHITECTURE.md
- [ ] 服务架构图与实际部署一致
- [ ] 端口信息与实际一致
- [ ] 数据流描述覆盖新增功能
- [ ] 安全设计描述与实现一致

### 2.6 README.md
- [ ] 版本号与 CHANGELOG 一致
- [ ] 技术栈版本号与实际一致（Go/Python/Next.js）
- [ ] Sprint 状态与 PROGRESS 一致
- [ ] 端口信息与 docker-compose.yml 一致
- [ ] 快速开始步骤可复现

### 2.7 CLAUDE.md
- [ ] 开发命令与实际一致
- [ ] 目录结构与实际一致
- [ ] 环境变量说明完整

---

## 三、视觉闭环检查

### 3.1 图标与品牌
- [ ] favicon 已设置
- [ ] 登录页 Logo 显示正常
- [ ] 首页 Header Logo 显示正常
- [ ] 暗黑模式下图标颜色正常

### 3.2 UI 一致性
- [ ] 新页面遵循 Notion-like 设计系统
- [ ] 暗黑模式颜色变量正确使用
- [ ] 间距/字重与 PRD 2.1 一致
- [ ] 动效存在（200-300ms ease-out）

---

## 四、提交前检查

- [ ] `git diff` 查看变更，确认无意外修改
- [ ] 无敏感信息泄露（grep password/key/secret）
- [ ] 提交信息遵循 Conventional Commits
- [ ] 提交前本地测试通过

---

## 五、Sprint 结束检查

- [ ] 所有代码提交到 develop 分支
- [ ] 所有文档同步完成
- [ ] CHANGELOG 已更新
- [ ] 可运行的版本（docker-compose up -d 可启动）
- [ ] 里程碑验证通过
- [ ] Push 到远程仓库
